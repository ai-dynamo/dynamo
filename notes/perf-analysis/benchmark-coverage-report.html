Dynamo benchmarking — three-tier coverage

What exists at each tier, what each covers, and where the request path is unmeasured.

Verified against origin/main @ cd6b63b0cc · working draft, not published guidance

§1The thesis

Layers are not a design principle to adopt up front. End-to-end measurement is primary; a component harness is justified only where e2e provably cannot answer the question. There is exactly one such case, and it is structural rather than a matter of resolution.

In a saturated system, only the bottleneck's capacity is observable. Everything else is idle-waiting, so its ceiling is invisible however finely you instrument. E2E names the current bottleneck; component isolation names the next one. The repo already recorded this: against mock workers the frontend sits at 60–85% of its pinned cores, so frontend optimizations "show flat e2e throughput."

§6What the map says

  • Both micro-level holes sit at the client-facing edges. HTTP ingress and SSE relay have no bench — precisely where a closed-loop client's latency is most sensitive, and precisely what mock workers cannot speak to, since the mocker replaces generation.
  • Tier 1 is weaker than it looks. Every stage reads "strong" at e2e only because the client interval contains it. With no server-side capture in any recipe, that column measures the whole and attributes nothing.
  • KV management inverts the usual pattern — better covered at tiers 2 and 3 than at tier 1, because its metrics exist but are never collected during a benchmark.
  • Coverage tracks authorship, not the request path. Stages are covered where the people building them happened to add benchmarks. Nobody maintains a view of the whole.
  • One dead entry. llm/benches/kv_router_bench.rs yields no bench functions while remaining compile-gated in CI — build cost plus implied coverage that is not there.
Provenance. Tier contents, the 0-of-33 instrumentation count, the port collision between the two frontend harnesses, and the bench inventory were all verified against the tree. Coverage ratings are judgment applied to those facts. The palette is the visualization skill's reserved status set, paired with glyph and label so no cell relies on color alone; its automated validator could not be run here (no JS runtime available), so the documented pre-validated values were used as published.
