# Policy changes and override review

The reusable `Compliance Policy Review` job feeds the required `pre-merge-status-check` aggregate on compliance-related PR changes and compares the exact base policy with the proposed policy. New global reciprocal or unclassified license grants are rejected. New or expanded package permissions require `version`, `usage`, `evidence`, and `reason`; `version` is an exact resolved artifact version, not a range. These fields make the review concrete; a passing schema check is not legal approval or proof of the claimed runtime use. Existing global grants and unscoped exceptions remain visible as legacy review debt without silently approving or deleting them. Factual rationale or evidence corrections that preserve the permission tuple are permitted and remain review debt; for example, pycountry is an executable Python library used by Outlines, not only data.

`license_overrides.yaml` corrects license metadata and does not grant distribution rights. New corrections use the same exact-version and evidence fields. An exact `(ecosystem, name, version)` correction wins over an existing versionless fallback. Duplicate YAML keys and duplicate identities fail loading. The three duplicate libdrm records were consolidated without changing their MIT corrections; both source descriptions remain.

The generator writes `override-usage.json` before base subtraction, recording the resolved package version, raw license metadata, resolved license, and whether an override lookup was actually applied. Finding a package in a CSV is not counted as applying its override. A pinned base inventory used for subtraction is bundled as `override-base.cdx.json` with its hash so a later report never substitutes the current branch's base inventory for a historical build's.

The scheduled and manually dispatched `Compliance Override Usage` workflow inspects the latest scheduled nightly with compliance artifacts, including red workflows whose artifact production succeeded. It verifies artifact/run/source identity, artifact digest, architecture and CUDA inventory identity, the historical override-catalog hash, and bundled base hashes against the declared `usage_matrix.json`. Missing artifacts or telemetry, expired evidence, or mismatched hashes make coverage incomplete and suppress cleanup candidates. Reports distinguish actual applications, matching but unused corrections, unobserved entries, metadata conflicts, and incomplete evidence. Candidates are for human review only: no records are deleted or approved, and nightly coverage does not establish that a correction is unused on retained releases or optional images.

The policy report evaluates SPDX expression structure. `MIT OR GPL-3.0-only` has a permissive alternative; `MIT AND GPL-3.0-only` does not. Separate DEP5 file sets are joined with parentheses around their alternatives so a permissive choice for one file set cannot bypass another file set's GPL requirements. This parser correction can expose existing policy violations, which require evidence-based review rather than blanket exceptions.

## Correcting source-package scope without weakening the gate

The DEP5 precedence fix exposed eight vLLM package findings: five are unused Mesa/video packages, while three retained libraries need their binary-license choices separated from source-package metadata and actually shipped packaging changelogs. Mesa also installed GPL-covered bug-report scripts, so its packages cannot simply be relabeled MIT.

The CUDA serving runtime now removes the reviewed unused set (`libplacebo338`, `libgl1`, `libglx0`, `libgbm1`, `libgl1-mesa-dri`, `libglx-mesa0`, and `mesa-libgallium`) after rebuilding headless OpenCV. The recorded final-image evidence covers both architectures. APT must propose exactly the requested installed native packages; automatic removal, extra removals, upgrades, and foreign-architecture removals are rejected. The build rejects GUI/OpenGL-enabled OpenCV or newly installed graphics bindings and checks OpenCV import, build information, and resizing again in a fresh process after removal. `libglvnd0`, the JIT toolchain, CUDA libraries, and unrelated packages are retained.

Six exact-version metadata corrections cover `libbpf1`, `libgraphite2-3`, `libibverbs-dev`, and the three AWS libfabric packages. [The evidence manifest](evidence/dpkg-license-corrections.json) records public binary/source URLs and hashes, build/install scope, original copyright texts, and comparisons with independently audited image bytes. Each correction requires the reviewed copyright hash and absence of its exact packaging-changelog entry. The cleanup checks version, copyright, license expression, changelog bytes or symlink target, and safe filesystem ancestry before deleting anything. It runs in the actual pre-runtime/pre-frontend filesystem and after EFA installation; cleaning only a scanner copy would be incorrect. Only the `libibverbs-dev` changelog symlink is removed, never the dependency-owned target. Copyrights, upstream license/notice files, and upstream manpages remain.

Unsupported versions remain untouched and uncorrected. Missing or changed evidence fails closed without falling back to a versionless correction. Registry-only baseline capture has no copyright bytes: it explicitly reports the unavailable evidence and validates the original scanner license instead. Rust/Python override callers cannot apply these dpkg-only predicates.

The corrected expressions preserve genuine license alternatives. Graphite remains reciprocal under its LGPL/MPL/GPL choices; this change neither calls it permissive nor waives source and notice obligations. No global allow/deny entries or package-exception permissions are added.


Configured baseline ownership is resolved before cleanup and scoped metadata resolution. Only exact dpkg name/version entries from the selected architecture's pinned baseline are excluded; missing or malformed baselines fail rather than disabling checks. Baseline-owned components remain untouched and are recorded as `baseline_owned` / `not_evaluated` in usage evidence. They are neither applied corrections nor certified-unused cleanup candidates. Packages with changed versions remain above baseline and retain every artifact predicate. This matters for TensorRT-LLM's inherited Graphite package, which appears in the configured baseline while its runtime base omits the copyright file. This preserves the configured attribution boundary; it does not independently establish legal approval of the base contents.
