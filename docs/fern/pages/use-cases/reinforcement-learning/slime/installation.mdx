## Prerequisites

- A [Kubernetes](https://kubernetes.io/docs/setup/) cluster with NVIDIA GPU nodes
- [`kubectl`](https://kubernetes.io/docs/tasks/tools/)
- [Helm](https://helm.sh/docs/intro/install/)

## Prepare the Cluster

<Steps toc={true}>
  <Step title="Install the Dynamo Kubernetes Platform">

Follow [Install Dynamo on Kubernetes](../../../kubernetes/installation/install-dynamo.md). The guide also covers the GPU Operator that provides the `nvidia.com/gpu` resource. The Slime and Dynamo images use CUDA 13, so the GPU nodes need NVIDIA driver 580 or later. The tutorial was validated with platform version 1.6.1.

  </Step>
  <Step title="Install the KubeRay operator">

KubeRay runs the Slime trainer as a `RayJob`. Install the operator with Helm:

```bash
helm repo add kuberay https://ray-project.github.io/kuberay-helm/
helm repo update
helm install kuberay-operator kuberay/kuberay-operator \
  --version 1.7.1 \
  --namespace kuberay \
  --create-namespace
```

Confirm that the operator is running:

```bash
kubectl get pods -n kuberay
```

```text
NAME                                READY   STATUS    RESTARTS   AGE
kuberay-operator-6b9c8d7f5d-x2q7z   1/1     Running   0          1m
```

  </Step>
  <Step title="Choose a shared StorageClass">

The trainer and the SGLang engines share one volume for the model, the dataset, and each weight update, so it needs the `ReadWriteMany` access mode. List the StorageClasses in your cluster:

```bash
kubectl get storageclass
```

Pick one whose provisioner supports `ReadWriteMany`, and note its name for the tutorial's `STORAGE_CLASS` variable.

  </Step>
  <Step title="Verify the installation">

```bash
kubectl get crd dynamographdeployments.nvidia.com rayjobs.ray.io
```

```text
NAME                                CREATED AT
dynamographdeployments.nvidia.com   2026-07-01T15:17:29Z
rayjobs.ray.io                      2026-07-09T18:47:32Z
```

  </Step>
</Steps>

## Included in the Images

You don't build, install, or clone Slime, Megatron-LM, SGLang, or Ray. The images that the tutorial uses already include them:

- The Slime image, `slimerl/slime:nightly-dev-20261027a-cu130`, has Slime 0.4.0 at `/root/slime`, Megatron-LM at `/root/Megatron-LM`, SGLang 0.5.21, PyTorch 2.13, and Ray 2.59.0. KubeRay runs `ray job submit` from this image, so you don't need Ray on your workstation.
- The Dynamo 1.6.1 `dynamo-frontend` image runs the Dynamo frontend, and the 1.6.1 `sglang-runtime` image has SGLang 0.5.21 and the Dynamo SGLang sidecar.

The tutorial was validated with these images on Azure Kubernetes Service (AKS) with Kubernetes 1.34, H100 80 GB GPUs, and an Azure Managed Lustre volume for shared storage.

Clone [Slime](https://github.com/THUDM/slime) only to change Slime itself, and use a revision that includes [THUDM/slime#2272](https://github.com/THUDM/slime/pull/2272).

## Hugging Face Access

The tutorial downloads the public `Qwen/Qwen3-0.6B` model and `zhuzilin/gsm8k` dataset, so it needs no token. For a gated model, create a Secret with your token and expose it as `HF_TOKEN` to the tutorial's setup Job, which runs the downloads.
