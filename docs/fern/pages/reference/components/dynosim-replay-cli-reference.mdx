`python -m dynamo.replay` extends the AI Simulate replay command with Dynamo KV router placement,
Planner scaling, Router-side NVIDIA AI Configurator modeling, and online-runtime execution.

The two commands share workload, trace, engine, topology, service-level agreement (SLA), and output
arguments. See [AI Simulate Replay CLI Reference](../../developer-guide/knowledge-base/modular-components/ai-simulate-experimental/replayer-experimental/cli-reference.md)
for those base options and the canonical report schema.

## Router Arguments

| Argument | Type | Default | Description |
|---|---|---|---|
| `--router-mode` | enum | `round_robin` | Selects `round_robin` or `kv_router` placement. |
| `--router-config` | JSON object | none | KV router policy configuration, such as queue policy or prompt-load model. |
| `--router-policy-config` | path | `DYN_ROUTER_POLICY_CONFIG` | Startup-only policy-family and cache-bucket queue YAML. Overrides the same field inside `--router-config`. |
| `--model-name` | string | none | Exact model profile selected from `--router-policy-config`. The root profile is used when unset. |

KV router replay maintains an in-process indexer and queues over the logical AI Simulate workers. It
uses replay time in offline mode and consumes neutral KV observations from the generalized engine.

Requests can set `policy_class` in compatible trace rows. A recognized policy family combines with
the Router-observed uncached Input Sequence Length (ISL) bucket. An exact explicit class bypasses
bucketing. Missing or unknown values use the selected profile's `default_policy_family`.

### Engine-Timing AIC Fields (Engine-Args JSON)

Engine timing remains part of the shared engine JSON passed through `--extra-engine-args`,
`--prefill-engine-args`, or `--decode-engine-args`. Configure `aic_backend`, `aic_system`,
`aic_model_path`, parallelism, quantization, and speculative-decoding fields there. See
[AI Simulate Replay CLI Reference](../../developer-guide/knowledge-base/modular-components/ai-simulate-experimental/replayer-experimental/cli-reference.md#engine-and-topology-arguments).

These engine fields change modeled pass duration. They are independent from the top-level
Router-side `--aic-*` arguments.

## Router-Side AIC Prompt-Load Flags

Use these top-level flags with `router_prefill_load_model: "aic"` in `--router-config`. They change
Router prompt-load estimation rather than generalized-engine timing.

| Argument | Type | Default | Description |
|---|---|---|---|
| `--aic-backend` | string | none | Backend for Router-side latency prediction. |
| `--aic-system` | string | none | GPU system identifier, such as `h200_sxm`. |
| `--aic-backend-version` | string | automatic | Backend version used by the model. |
| `--aic-model-path` | string | none | Hugging Face model identifier. |
| `--aic-tp-size` | positive integer | `1` | Tensor-parallel size. |
| `--aic-moe-tp-size` | positive integer | none | Mixture-of-Experts tensor-parallel size. |
| `--aic-moe-ep-size` | positive integer | none | Mixture-of-Experts expert-parallel size. |
| `--aic-attention-dp-size` | positive integer | none | Attention data-parallel size. |
| `--aic-gemm-dtype` | string | model default | Dense general matrix multiplication quantization mode. |
| `--aic-moe-dtype` | string | model default | Mixture-of-Experts quantization mode. |
| `--aic-fmha-dtype` | string | model default | Fused multi-head attention quantization mode. |
| `--aic-kv-cache-dtype` | string | model default | KV-cache quantization mode. |
| `--aic-comm-dtype` | string | model default | Collective-communication quantization mode. |
| `--aic-nextn` | nonnegative integer | none | Speculative-decode draft depth. |
| `--aic-nextn-accept-rates` | comma-separated floats | none | Conditional draft-token acceptance rates. |

Router-side AI Configurator modeling requires backend, system, and model identity. The command fails
before replay when required fields are missing.

## Planner Arguments

| Argument | Type | Default | Description |
|---|---|---|---|
| `--planner-config` | path or inline JSON | none | Enables Planner-in-the-loop replay with the supplied configuration. |
| `--benchmark-granularity` | positive integer | `8` | Synthetic performance-model points used to bootstrap Planner throughput regression. |

Planner replay supports aggregated and disaggregated offline simulation. The Planner configuration
mode must match the selected engine topology. Disaggregated Planner replay requires both prefill and
decode engine arguments.

Planner replay accepts Mooncake and Dynamo request traces. It does not support
`--max-sim-time-seconds`. Scale decisions, worker-count changes, and diagnostics are added to the
Dynamo report around the canonical AI Simulate replay result.

## Online Runtime

Set the shared `--replay-mode online` argument to run through Dynamo's live simulated-worker path.
Online replay includes worker registration, request transport, event publication, and runtime
coordination. It requires the Dynamo runtime and is not available through
`python -m aisimulate.replay`.

Online per-request JSONL output currently requires a trace-file workload. Planner-in-the-loop replay
supports only offline mode.

For direct frontend and worker testing rather than trace replay, use `python -m dynamo.mocker` and
the [Mocker CLI Reference](mocker-cli-reference.mdx).

## Dynamo Constraints

- `--planner-config` requires `--replay-mode offline`.
- Planner trace replay supports only `mooncake` and `dynamo` trace formats.
- `--max-sim-time-seconds` cannot be combined with `--planner-config`.
- Offline KV router placement requires more than one worker, DP-rank target, or scaling-enabled
  composition.
- Disaggregated replay requires matching prefill and decode backends and does not support
  TensorRT-LLM or attention-DP.
- Online replay uses the Dynamo Live Mocker runtime and its supported topology constraints.
