The vLLM-Omni backend uses a dedicated entrypoint: `python -m dynamo.vllm.omni`. This page documents its CLI flags. For deployment guides and per-modality examples, see the [Diffusion Overview](../../use-cases/diffusion/overview.md).

<Note>
These are the vLLM-Omni orchestration flags. The omni worker also accepts the same underlying vLLM engine arguments and the cross-cutting [Dynamo Runtime](../components/runtime-configuration.mdx) flags (`--namespace`, `--endpoint`, and others).
</Note>

## General Flags

<ParamField path="--omni" type="flag">
  Enable the vLLM-Omni orchestrator (required for all omni workloads).
</ParamField>
<ParamField path="--output-modalities" type="text | image | video | audio">
  Output modality the worker registers endpoints for.
</ParamField>
<ParamField path="--stage-configs-path" type="path">
  Path to stage config YAML (optional; vLLM-Omni uses model defaults if omitted).
</ParamField>
<ParamField path="--boundary-ratio" type="float">
  MoE expert switching boundary. If omitted, the vLLM-Omni model pipeline selects its default.
</ParamField>
<ParamField path="--flow-shift" type="float">
  Scheduler flow_shift (5.0 for 720p, 12.0 for 480p).
</ParamField>
<ParamField path="--default-video-fps" type="int" default="16">
  Default frames per second for generated videos.
</ParamField>
<ParamField path="--task-type" type="string">
  Model-defined startup task or checkpoint partition.
</ParamField>
<ParamField path="--no-guardrails" type="flag" default="false">
  Disable native model guardrails, such as Cosmos3 guardrails, for an aggregated
  Omni worker. The environment equivalent is `DYN_OMNI_NO_GUARDRAILS=true`.
  Omitting the option preserves the model's guardrail configuration and its
  dependency requirements. Standalone stages, the stage router, and realtime
  workers reject this option.
</ParamField>
<ParamField path="--lora-path" type="path ...">
  Diffusion checkpoint adapter path(s) fused into the model at startup. This is
  separate from request-time LoRA loading.
</ParamField>
<ParamField path="--diffusion-attention-backend" type="string">
  Default diffusion attention backend, such as `TRTLLM_ATTN`, `FLASH_ATTN`, or
  `FASTVIDEO_VSA`.
</ParamField>
<ParamField path="--fastvideo-vsa-topk" type="int">
  Key/value blocks retained per query block by `FASTVIDEO_VSA`. The value must
  be positive; FastH3 VSA starts with 64.
</ParamField>

## Image Edit Capabilities

**Experimental.** Direct uploads and multiple ordered references are supported
through the unified Omni entrypoint when its loaded pipeline advertises a
finite image limit in the installed Omni registry. The adapter resolves the
actual pipeline class, including upstream aliases, independently of the
client's model name. Dynamo stage-worker deployments without this capability
advertisement remain limited to one reference.

| Resolved pipeline | Source-derived maximum | Metadata source |
|---|---:|---|
| `Flux2KleinPipeline` | 4 | vLLM-Omni 0.31.0rc1 |
| `QwenImageEditPlusPipeline` | 4 | vLLM-Omni 0.31.0rc1 |
| `HunyuanImage3Pipeline` | 3 | vLLM-Omni 0.31.0rc1 |
| `BooguImagePipeline` | 1 | vLLM-Omni 0.31.0rc1 |

This table describes registry metadata, not GPU qualification of every model.
FLUX.2 Klein 4B was GPU-qualified on one GH200 with vLLM 0.31.0,
vLLM-Omni 0.31.0rc1, and model revision
`e7b7dc27f91deacad38e78976d1f2b499d76a294`: one through four inputs,
a rejected fifth input, and a changed output when only input two changed.
Multipart and JSON produced identical pixels for the same inputs, prompt, and
seed at 512 by 512 pixels and four denoising steps. This checks conditioning
and transport behavior; it is not an output-quality or throughput benchmark.

Missing, invalid, or unknown metadata permits at most one reference; it does
not establish that a pipeline implements editing. Omni 0.31.0rc1 does not
expose a universal single-image-edit support flag. In particular,
`supports_multimodal_inputs=False` does not prove that editing is unsupported.
Dynamo therefore preserves the existing single-image path for those pipelines.

Set `DYN_IMAGE_EDIT_MAX_IMAGES`, `DYN_IMAGE_EDIT_MAX_PIXELS`, and
`DYN_IMAGE_EDIT_MAX_TOTAL_PIXELS` on the worker to lower its input budgets.
The worker advertises the smaller of the model and configured count limits,
then rechecks every request before loading inputs. A failed second or later
reference never becomes a successful partial edit. These settings do not
change `n`, output dimensions, or output encoding.

See [Image API Compatibility](../components/frontend-configuration.mdx#image-api-compatibility)
for the request contract, all resource defaults, and rolling-upgrade behavior.

## Memory & Performance

<ParamField path="--image-png-compression-level" type="int" default="6">
  Lossless PNG compression level for generated images, from `0` to `9`.
  `0` disables compression for faster CPU encoding and larger responses;
  `1` uses fast compression, and `9` uses the strongest compression. The default
  `6` preserves Pillow's existing encoding behavior. All levels preserve pixels.

  Set `DYN_OMNI_IMAGE_PNG_COMPRESSION_LEVEL` as an environment alternative;
  an explicit CLI value takes precedence. Invalid values fail startup.
  Set this on the aggregated worker, or on the `--omni-router` process in
  disaggregated mode. It applies to PNG images returned as base64, stored for
  URL responses, or embedded in chat responses. It does not change model
  inference or video encoding.

  Measure both encoding time and end-to-end latency when tuning this setting:
  larger payloads can offset CPU savings on slower networks. Compare backends
  at matched PNG compression levels, and report first-request and warm latency
  separately from model-loading time.
</ParamField>
<ParamField path="--vae-use-slicing" type="flag">
  Enable VAE slicing for memory optimization.
</ParamField>
<ParamField path="--vae-use-tiling" type="flag">
  Enable VAE tiling for memory optimization.
</ParamField>
<ParamField path="--enable-layerwise-offload" type="flag">
  Enable layerwise offloading on DiT modules to reduce GPU memory.
</ParamField>
<ParamField path="--layerwise-num-gpu-layers" type="int">
  <Warning>
    This legacy option is no longer supported and causes a configuration error
    when set. Remove the flag or unset `DYN_OMNI_LAYERWISE_NUM_GPU_LAYERS`.
    Use `--enable-layerwise-offload` without a layer-count override to let
    vLLM-Omni manage layerwise offloading.
  </Warning>
</ParamField>
<ParamField path="--enforce-eager" type="flag">
  Disable torch.compile for diffusion models.
</ParamField>
<ParamField path="--enable-cpu-offload" type="flag">
  Enable CPU offloading for diffusion models.
</ParamField>

## Parallelism

<ParamField path="--ulysses-degree" type="int" default="1">
  GPUs for Ulysses sequence parallelism in diffusion.
</ParamField>
<ParamField path="--ring-degree" type="int" default="1">
  GPUs for ring sequence parallelism in diffusion.
</ParamField>
<ParamField path="--cfg-parallel-size" type="int" default="1">
  GPUs for classifier-free guidance parallelism (1 or 2).
</ParamField>
<ParamField path="--vae-patch-parallel-size" type="int" default="1">
  Ranks used for VAE patch or tile parallelism.
</ParamField>
<ParamField path="--text-encoder-tp-size" type="int" default="1">
  Tensor-parallel ranks used by the diffusion text encoder.
</ParamField>

</ParamField>

  Run as the stage router. Requires `--stage-configs-path`. Mutually exclusive with `--stage-id`.
