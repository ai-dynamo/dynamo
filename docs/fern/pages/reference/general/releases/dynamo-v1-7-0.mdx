Dynamo v1.7.0 is the 20th feature release of the open-source distributed inference platform, spanning 763 merged PRs from 150 contributors. **Global Router** introduces cross-pool routing: a discovery service registers pools and routers, and **Dynamo Frontend** balances traffic across pools by load with session affinity. **Dynamo Planner** adds batch scheduling, pool-priority GPU budget trades, and an experimental live retune loop, while **Dynamo Router** adds deadline-ordered queues and transfer-island KV fetch hints. On Kubernetes, **Dynamo Operator** runs simulation-backed deployment searches and deploys multinode **Dynamo Sidecar** workloads. **Dynamo Sidecar** now recovers automatically when an engine dies, and Dynamo Frontend migrates eligible in-flight requests to another worker when `--migration-limit > 0`. For **Dynamo Enterprise**, `vllm-runtime-enterprise` now builds on the certified NVIDIA NIM vLLM base image, a production-ready vLLM container with security hardening. The engines move to SGLang v0.5.23, TensorRT-LLM v1.4.0rc2, and vLLM v0.33.0.

## Features & Improvements

### Scheduling

- **Planner Batch Scheduling Policy:** Added an opt-in batch scheduling policy that computes safe replica and idle targets with admission caps ([#14195](https://github.com/ai-dynamo/dynamo/pull/14195)), backed by shared observation and decision contracts ([#14198](https://github.com/ai-dynamo/dynamo/pull/14198)), new demand and load observation sources ([#14196](https://github.com/ai-dynamo/dynamo/pull/14196)), and a native runtime with leased, fenced execution ([#14197](https://github.com/ai-dynamo/dynamo/pull/14197)), all wired into Planner's tick lifecycle for consistent scaling decisions ([#14200](https://github.com/ai-dynamo/dynamo/pull/14200)).
- **Global Planner Pool Priority Ordering:** Added pool priority configuration and a resolver to Dynamo Planner without altering scaling decisions ([#17859](https://github.com/ai-dynamo/dynamo/pull/17859)), then used priority to pick scale-up donors and scale-down recipients, falling back to a finer-grained partner when needed ([#17860](https://github.com/ai-dynamo/dynamo/pull/17860)), and made equal-priority partners prefer the requesting participant over GPU delta ([#14036](https://github.com/ai-dynamo/dynamo/pull/14036)).
- **Global Discovery Service Added:** Added a discovery service for Global Router pool and router registration ([#17331](https://github.com/ai-dynamo/dynamo/pull/17331)), exposed over HTTP via `POST /pools`, `GET /pools`, `GET /routers`, `POST /routers`, and `GET /healthz` ([#17371](https://github.com/ai-dynamo/dynamo/pull/17371)). Added a client for pool registration and router lookup through `POST /pools` and `GET /routers` ([#17208](https://github.com/ai-dynamo/dynamo/pull/17208)), then added pool caching merging results into a watch channel ([#17702](https://github.com/ai-dynamo/dynamo/pull/17702)).
- **Global Router Pool Views:** Added live, per-pool routing views that track Pool Relay connections and reject stale updates after a reconnect ([#17196](https://github.com/ai-dynamo/dynamo/pull/17196)), and enabled resilient snapshot broadcasting to routers with automatic retries on failed attachments ([#17323](https://github.com/ai-dynamo/dynamo/pull/17323)).
- **Relay-Scoped Pool Load Tracking:** Kept each pool's load reports tied to the replica that sent them, pairing serving and KV load from the same source, validating report versions, and ranking pools from a single fresh view ([#17686](https://github.com/ai-dynamo/dynamo/pull/17686)). Added periodic polling of the router list to keep this view updated ([#17688](https://github.com/ai-dynamo/dynamo/pull/17688)).
- **Planner Live Retune Loop:** Added an experimental, simulation-only retune loop that replays a recorded trace to search runtime-changeable Router and Planner fields and applies improvements that beat a configurable minimum gain ([#17095](https://github.com/ai-dynamo/dynamo/pull/17095)), with an option to score candidates on a custom objective metric ([#17540](https://github.com/ai-dynamo/dynamo/pull/17540)). Extended the loop to live Planners for trace replay from storage with Kubernetes integration ([#17483](https://github.com/ai-dynamo/dynamo/pull/17483)).
- **KV State Agent Scale-Out:** Moved state-agent events onto the pooled direct-ZMQ fan-in and narrowed reconciliation to re-plan only affected CacheOwners ([#16568](https://github.com/ai-dynamo/dynamo/pull/16568)), and relocated the agent's outbound cursor to swap status snapshots only on lifecycle changes ([#16935](https://github.com/ai-dynamo/dynamo/pull/16935)). Connected SGLang HiCacheStorage's KVCR-owned inventory to the state agent so peer-fetch hints reflect actual KVCR DRAM residency ([#17531](https://github.com/ai-dynamo/dynamo/pull/17531)).
- **Mooncake HiCache Session Residency:** Tracked session prefix depth per worker and storage tier across GPU, host-pinned memory, and disk ([#16501](https://github.com/ai-dynamo/dynamo/pull/16501)), extending this to SGLang's direct external linker path ([#16610](https://github.com/ai-dynamo/dynamo/pull/16610)). Scoped HiCache hits to the correct tenant ([#16385](https://github.com/ai-dynamo/dynamo/pull/16385)) and enabled router hint forwarding in the in-process SGLang backend ([#16117](https://github.com/ai-dynamo/dynamo/pull/16117)). Added a bench-only KVCR host-tier mode for tiered lookup testing ([#17353](https://github.com/ai-dynamo/dynamo/pull/17353)).
- **Lower-Tier Lookup Speed Improvements:** Reduced hinted lookup cost for HostPinned and KVCR tiers, cutting latency at 256 workers and 4K-block prompts from about 5 ms to about 0.5 ms ([#16436](https://github.com/ai-dynamo/dynamo/pull/16436)), shrank edge-table and reverse-index memory per slot ([#17143](https://github.com/ai-dynamo/dynamo/pull/17143)), and extended the single-worker fast path to one-hint chains ([#17149](https://github.com/ai-dynamo/dynamo/pull/17149)).
- **Topology-Aware KV Fetch Hints:** Added fetch-source selection that uses topology-aware KV transfer metadata so a `kv.fetch` hint only names a source in the target's transfer island ([#16477](https://github.com/ai-dynamo/dynamo/pull/16477)), merged worker selection and fetch-source choice into one decision ([#16701](https://github.com/ai-dynamo/dynamo/pull/16701)), and added single-source fetch continuations that extend a worker's existing prefix from a source holding only the missing blocks ([#17657](https://github.com/ai-dynamo/dynamo/pull/17657)).
- **ZMQ Replay Recovery:** Added opt-in recovery for ZMQ KV event sources so the local KV index can catch up with the vLLM engine after a connection drop and resume tracking live events ([#16751](https://github.com/ai-dynamo/dynamo/pull/16751)). Shared ZMQ contexts across services and reused replay connections to reduce overhead and improve reliability ([#17253](https://github.com/ai-dynamo/dynamo/pull/17253)).
- **Policy-Queue Busy-Reject Thresholds:** Added a `decode_busy_threshold_frac` option that marks a worker busy when its active requests exceed that fraction of `total_kv_blocks` ([#16618](https://github.com/ai-dynamo/dynamo/pull/16618)). Moved busy-worker rejection in KV mode into the KV router queue so thresholds apply consistently across policies ([#16619](https://github.com/ai-dynamo/dynamo/pull/16619)).
- **EDF Ordering For Policy Queues:** Added earliest-due-first ordering to Dynamo Router policy-class queues, sorting requests by deadline or ingress time plus `slo_ttft_ms`, defaulting YAML policy classes to EDF while keeping FCFS for synthetic classes ([#17724](https://github.com/ai-dynamo/dynamo/pull/17724)).
- **Policy Queue Controlled Delay:** Added opt-in expiry enforcement to EDF policy-class queues in Dynamo Router, rejecting requests whose due time passes before admission even when downstream workers remain busy ([#17725](https://github.com/ai-dynamo/dynamo/pull/17725)).
- **External Session Replication:** Enabled external hosts, such as ray, to replicate session affinity bindings and TTL refreshes from the built-in mesh ([#16969](https://github.com/ai-dynamo/dynamo/pull/16969)), and added a rate-limited warning when the replication channel closes outside shutdown ([#17537](https://github.com/ai-dynamo/dynamo/pull/17537)).
- **Configurable Session-Affinity Entry Limit:** Added `--router-session-affinity-max-entries` / `DYN_ROUTER_SESSION_AFFINITY_MAX_ENTRIES` so the per-frontend session-affinity table can hold more than the previously hard-coded 65,536 sessions, with the default unchanged ([#18240](https://github.com/ai-dynamo/dynamo/pull/18240)), and fixed the environment variable to be read from the frontend parser environment rather than `os.environ` ([#18341](https://github.com/ai-dynamo/dynamo/pull/18341)).
- **Two-Tier KV Default Notice:** Added a startup `WARN` when `--router-mode kv` runs without a worker-selection policy, noting Dynamo 1.8 will default to `dynamo-two-tier-cost-fn` and how to keep `dynamo-default-cost-fn` via `--router-policy-config` ([#17792](https://github.com/ai-dynamo/dynamo/pull/17792)).
- **Scheduler Queue Actor Hot Path:** Moved candidate row construction off the router's serial scheduler queue actor onto the caller task, running in parallel across requests ([#17465](https://github.com/ai-dynamo/dynamo/pull/17465)). Changed the queueing capacity gate to check one rank's load only when needed, instead of projecting every rank on each operation ([#17480](https://github.com/ai-dynamo/dynamo/pull/17480)).
- **Serving Load Streaming API:** Added a `SubscribeServingLoad` gRPC endpoint so a global load balancer can watch router and frontend load, enabled only when `DYN_SERVING_LOAD_PUBLISH` is set ([#13187](https://github.com/ai-dynamo/dynamo/pull/13187)).
- **Declared GPU Cost Fallback:** Added a selector-keyed `gpu_cost` table so GPU-free mocker pools can declare a cost and join Global Planner budget arbitration instead of being rejected as unpriced ([#14055](https://github.com/ai-dynamo/dynamo/pull/14055)).
- **Sticky Min-Load Routing Policy:** Added `dynamo-sticky-min-load`, a worker-selection policy that pins each session to its first-bound, least-loaded worker via `X-Dynamo-Session-ID`, avoiding re-prefill penalties from load-based routing ([#15600](https://github.com/ai-dynamo/dynamo/pull/15600)).
- **Per-Phase Worker Request Gauge:** Added `dynamo_frontend_worker_active_requests`, a gauge exposing active requests per worker and DP rank by phase (prefill or decode), aiding attention-DP routing, debugging, and autoscaling ([#15666](https://github.com/ai-dynamo/dynamo/pull/15666)).
- **Reduced Dispatch Allocation Overhead:** Optimized worker membership checks to avoid unnecessary discovery copies, cutting allocation overhead during prepared dispatch ([#15974](https://github.com/ai-dynamo/dynamo/pull/15974)).
- **Sparse Worker Eligibility Scan:** Changed router filtering to scan the smaller allowed-worker or availability set instead of the full worker catalog when that set is under half the catalog size, cutting CPU time for sparse checks ([#15992](https://github.com/ai-dynamo/dynamo/pull/15992)).
- **KV Router Lookup Improvement:** Replaced the O(N²) prefill queue scan with a BTreeMap-based lookup, cutting removal time to O(log N) and reducing CPU usage by 75.9% in benchmarks ([#15993](https://github.com/ai-dynamo/dynamo/pull/15993)).
- **KV Router Map Capacity:** Added pre-allocated capacity for temporary worker maps in Dynamo Router's overlap projection, reducing map growth at large worker counts and CPU usage in affected paths ([#16018](https://github.com/ai-dynamo/dynamo/pull/16018)).
- **Sharded KV-Metrics Mailbox Lock:** Reduced mailbox lock contention by sharding the active-load mailbox into 16 shards keyed by worker ID and data-parallel rank, cutting lock-wait time from 52.2 ms to 0.02 ms per request ([#16118](https://github.com/ai-dynamo/dynamo/pull/16118)).
- **Worker-Set Storage Optimization:** Changed Dynamo Frontend's worker-set membership storage to a copy-on-write structure, cutting CPU usage by about 10% on high-core-count hosts ([#16119](https://github.com/ai-dynamo/dynamo/pull/16119)).
- **Router Selection Trace Records:** Added an opt-in `router_selection` request-trace record and trace-level `Scored worker candidate` logs exposing per-worker scoring costs, letting operators see why Dynamo Router picked a worker ([#16395](https://github.com/ai-dynamo/dynamo/pull/16395)).
- **Runtime Router Policy API:** Added `/router_policy` and `/router_policy/busy_threshold` HTTP endpoints to update live worker-selection parameters and model-level busy thresholds, with revision checks to reject stale writes and reset to startup values ([#16818](https://github.com/ai-dynamo/dynamo/pull/16818)). The endpoints are served on the Frontend admin listener, which is off by default; set `DYN_ENABLE_FRONTEND_ADMIN_API=1` and call `127.0.0.1:8002`, which on Kubernetes means `kubectl port-forward` to the frontend pod ([#17165](https://github.com/ai-dynamo/dynamo/pull/17165)).
- **Planner Runtime Reconfiguration:** Enabled controllers to update a running Dynamo Planner's budgets, SLA targets, and scaling thresholds via a new `/engine/planner/config` endpoint without restarting the process ([#16843](https://github.com/ai-dynamo/dynamo/pull/16843)).
- **TensorRT-LLM Render Protocol Support:** Added a `trtllm-render` tokenizer protocol enabling the standalone EPP to route KV-aware traffic to stock `trtllm-serve` workers using a shared render client across vLLM, SGLang, and TensorRT-LLM ([#17038](https://github.com/ai-dynamo/dynamo/pull/17038)).
- **Smaller KV Indexer Slots:** Reduced the KV router's `BlockLookup` slot size, cutting memory use by about a quarter and lowering heap and RSS by roughly 15-16 GiB in benchmarks ([#17109](https://github.com/ai-dynamo/dynamo/pull/17109)).
- **Local Execution Profiles:** Dynamo Planner can now load local AISimulate execution profiles via `ais_perf_model.dataset_profiles.<role>.{root,manifest}` for prefill, decode, and aggregated roles ([#17228](https://github.com/ai-dynamo/dynamo/pull/17228)).
- **Faster KV Router Parsing:** Changed selection request parsing to use a typed conversion for token IDs, cutting CPU cost and increasing throughput by 85% ([#17238](https://github.com/ai-dynamo/dynamo/pull/17238)).
- **Pool Model From Registrations:** Changed the Global Discovery Service so `POST /pools` now accepts registrations under MCS pool discovery instead of returning HTTP 501, reading each pool's model and capacity from the PoolRelay's heartbeat ([#17332](https://github.com/ai-dynamo/dynamo/pull/17332)).
- **Faster Token Extraction:** Optimized `token_ids` reads by index instead of iterator, reducing CPU overhead on `select_and_reserve` calls ([#17337](https://github.com/ai-dynamo/dynamo/pull/17337)).
- **Early Decode Terminal Delivery:** Changed the prefill router to forward a successful decode terminal immediately instead of waiting for prefill completion, reducing delay on short answers in disaggregated serving ([#17484](https://github.com/ai-dynamo/dynamo/pull/17484)).
- **Global Frontend Affinity Routing:** Added `--router-policy affinity` to Dynamo Frontend, which selects pools by load and pins each session to one pool, moving it only when another pool has much more headroom ([#17524](https://github.com/ai-dynamo/dynamo/pull/17524)).
- **LPX Engine Load Publishing:** Added polling of the engine's load call to publish KV cache load through the worker's load publisher, matching TensorRT-LLM behavior and enabling the router's busy-worker check for LPX workers ([#17539](https://github.com/ai-dynamo/dynamo/pull/17539)).
- **Moved Router Log Handling:** Moved the "Selected worker" log out of the KV router's scheduler actor into the routing task, improving throughput under concurrent load while keeping log output unchanged ([#17700](https://github.com/ai-dynamo/dynamo/pull/17700)).
- **Faster Token Block Hashing:** Improved token hashing to work directly on token windows without copying, cutting benchmark times by 63-86% while keeping hash values unchanged ([#15701](https://github.com/ai-dynamo/dynamo/pull/15701)).

### Frontend & Agents

## Looking Ahead

### Router Hint Policies

Hint policies join request classifiers and worker-selection policies as a third router plugin role, and KV Cache Reuse worker selection and the KV fetch hint move out of router core into plugins.

### Global Router Shared State

Global Router can persist session affinity in DynamoDB, and Global Discovery Service can share pool and router registrations across replicas and regions through one DynamoDB table.

### Runtime LoRA Placement & Routing

Runtime LoRA adapters gain a placement policy and run through hosted and KV-aware routing, while legacy adapter behavior stays unchanged.

### Planner Retune with Scaling & Pareto Search

Live retune through DGDR v1beta2 extends from router-only settings to a Planner with load or throughput scaling, and DGDR v1beta2 gains Pareto multi-objective search.

### Custom Chat Processors

Any `--dyn-chat-processor` value other than `dynamo`, `vllm`, or `sglang` loads a custom Python chat processor that keeps worker error status and can set response headers.
