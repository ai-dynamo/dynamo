Dynamo v1.6.0 is the 19th feature release of the open-source distributed inference platform, spanning 654 merged PRs from 148 contributors. **Dynamo Router** gains pluggable flow control: request classifiers can defer, reorder, or steer requests, and every selection path now runs on one shared core with scoring knobs consolidated into one policy file. On Kubernetes, LPX brings LPU-backed inference to DynamoGraphDeployments, multinode components take role-specific pod templates, and Dynamo Snapshot backs engine failover. **Dynamo Planner** reconfigures GPU budgets at runtime, and the engines move to SGLang v0.5.21, TensorRT-LLM v1.3.0rc29, and vLLM v0.31.0.

<Note>
Breaking changes and deprecations for this release are tracked on the [Deprecations](deprecations.mdx#v160) ledger; known issues on the [Known Issues](known-issues.mdx#v160) page. ## Features & Improvements

### Frontend & Agents

- **Responses Tool Selection Hardening:** Rejected unsupported tools and `tool_choice` variants on `/v1/responses` with an actionable HTTP 400 instead of dropping them silently ([#14440](https://github.com/ai-dynamo/dynamo/pull/14440)), supported function-only `tool_choice.allowed_tools` ([#14990](https://github.com/ai-dynamo/dynamo/pull/14990)), removed text-based tool call inference from non-streaming responses ([#14846](https://github.com/ai-dynamo/dynamo/pull/14846)), and restored original function names and namespaces ([#15401](https://github.com/ai-dynamo/dynamo/pull/15401)).
- **Parsers V2 Structural Tags:** Added opt-in V2 parsers for GLM, DeepSeek V4/V4.1, Kimi K2/K3, Gemma 4, Muse, and Qwen3 ([#14950](https://github.com/ai-dynamo/dynamo/pull/14950)), configured through `--dyn-structural-tag` ([#16217](https://github.com/ai-dynamo/dynamo/pull/16217)). Structural tags are on by default for supported parsers ([#15916](https://github.com/ai-dynamo/dynamo/pull/15916)), and vLLM tool-call tags can start inside reasoning ([#16220](https://github.com/ai-dynamo/dynamo/pull/16220)).
- **KServe Tensor Protocol Fidelity:** Added half-precision `Float16` and `BFloat16` KServe tensor variants ([#14150](https://github.com/ai-dynamo/dynamo/pull/14150)), reported `ModelMetadata` datatypes by KServe v2 wire names ([#14957](https://github.com/ai-dynamo/dynamo/pull/14957)), and translated Triton `ModelConfig.dims` to KServe shapes ([#14996](https://github.com/ai-dynamo/dynamo/pull/14996)).
- **Semantic Error HTTP Mapping:** Centralized semantic error mapping to HTTP status codes in Dynamo Frontend for protocol-correct OpenAI and Anthropic failures without internal diagnostics ([#14396](https://github.com/ai-dynamo/dynamo/pull/14396)), and extended the JSON error envelope to the remaining OpenAI routes ([#14002](https://github.com/ai-dynamo/dynamo/pull/14002)).
- **DeepSeek V4.1 Frontend Support:** Added mainline frontend support for DeepSeek V4.1 Flash reasoning and tool calling, enabled when workers pass both `--dyn-tool-call-parser deepseek_v41` and `--dyn-reasoning-parser deepseek_v41` ([#15030](https://github.com/ai-dynamo/dynamo/pull/15030)), with native V4.1 image inputs and tool-result image ordering aligned to the rendered prompt by consuming the selected formatter's media order from `dynamo-renderer` ([#15097](https://github.com/ai-dynamo/dynamo/pull/15097)).
- **SSE Streaming Lifecycle Hardening:** Reworked SSE streams to end on a hard kill, not a graceful stop, so delayed events still finish ([#14645](https://github.com/ai-dynamo/dynamo/pull/14645)), and made streaming handlers wait for the first backend event so an exception before output returns the non-streaming HTTP status ([#14662](https://github.com/ai-dynamo/dynamo/pull/14662)).
- **Tokenizer Cache Lifecycle Hardening:** Replaced the process-global tokenizer pool with a weak-reference registry that shuts down each tokenizer's thread pool once collected ([#13368](https://github.com/ai-dynamo/dynamo/pull/13368)), and turned `DYN_TOKENIZER_CACHE_BYTES` into one combined budget per process, keeping the 64 MiB default ([#15387](https://github.com/ai-dynamo/dynamo/pull/15387)).
- **Root-Level Thinking Token Budget:** Added a root-level `thinking_token_budget` field to chat completion and Responses requests ([#12624](https://github.com/ai-dynamo/dynamo/pull/12624)) and carried it into SGLang, which requires strict-thinking mode and a reasoning parser ([#15120](https://github.com/ai-dynamo/dynamo/pull/15120)).
- **SGLang Cross-Encoder Reranking Endpoint:** Added an OpenAI-compatible `POST /v1/rerank` endpoint for SGLang text-only cross-encoder models with a dedicated `--rerank-worker` mode and support for `top_n` ([#14032](https://github.com/ai-dynamo/dynamo/pull/14032)), and fixed scheduler crashes in rerank workers serving XLM-RoBERTa cross-encoders ([#16286](https://github.com/ai-dynamo/dynamo/pull/16286)).
- **Frontend HTTP Mutual TLS:** Added a `--tls-client-ca-cert-path` flag and `DYN_TLS_CLIENT_CA_CERT_PATH` environment variable to the frontend HTTP server, requiring a CA-signed client certificate when set, with validation that rejects a client CA supplied without both a server certificate and key. Server-only TLS behavior remained unchanged ([#14173](https://github.com/ai-dynamo/dynamo/pull/14173)).
- **Opt-In Jemalloc Preload:** Added an opt-in jemalloc allocator preload for `python -m dynamo.frontend`, activated by `DYN_FRONTEND_JEMALLOC=1`, that continues with the default allocator when the library is missing ([#14678](https://github.com/ai-dynamo/dynamo/pull/14678)), with `libjemalloc2` installed in the SGLang, TensorRT-LLM, and vLLM runtime images so the switch takes effect ([#13101](https://github.com/ai-dynamo/dynamo/pull/13101)) and documentation on bounding frontend host memory growth ([#13099](https://github.com/ai-dynamo/dynamo/pull/13099)).
- **Typed Chunk Metrics Path:** Carried chunk metrics in the typed `llm_metrics` field instead of annotation comments, reducing mean inter-token latency by 6.21% with a 5.57% gain in output token throughput in a local A/B run ([#15115](https://github.com/ai-dynamo/dynamo/pull/15115)).
- **Opaque Agent Header Preservation:** Replaced the agent-compaction field with an `agent_headers` map of the `x-claude-code-*` and `x-codex-*` header families, so new coding-agent hints no longer require an envelope schema change ([#15367](https://github.com/ai-dynamo/dynamo/pull/15367)).
- **Raw Completion Stop Preservation:** Added an optional `no_stop_trim` field to `/v1/completions` that retains matched stop strings and stop/EOS token text so callers can see terminal markers, defaulting to false ([#15519](https://github.com/ai-dynamo/dynamo/pull/15519)).

### Scheduling

- **Session Prefix Indexing and Lineage:** Added an opt-in session prefix index (`--enable-session-prefix-index`) that tracks the KV blocks each session has built per worker and DP rank from vLLM KV events ([#13807](https://github.com/ai-dynamo/dynamo/pull/13807), [#13806](https://github.com/ai-dynamo/dynamo/pull/13806)), hardened worker-removal handling and capped session identifiers at 256 bytes ([#15362](https://github.com/ai-dynamo/dynamo/pull/15362)), and grouped subagent requests under their parent session so they land on one worker ([#14521](https://github.com/ai-dynamo/dynamo/pull/14521)).
- **Standalone EPP Routing Enablement:** Passed `expected_output_tokens` and `policy_class` from the standalone endpoint picker (EPP) into its selection service ([#13595](https://github.com/ai-dynamo/dynamo/pull/13595)), routed runtime EPP requests by the `x-dynamo-meta-policy-class` header ([#14480](https://github.com/ai-dynamo/dynamo/pull/14480)), added cache namespace and salt resolution ([#13714](https://github.com/ai-dynamo/dynamo/pull/13714)) and `sglang-renderer` tokenizer support ([#14501](https://github.com/ai-dynamo/dynamo/pull/14501)), and made native EPP atomically reserve KV-routed prefill capacity ([#13042](https://github.com/ai-dynamo/dynamo/pull/13042)).
- **Pluggable Router Flow Control:** Added a pluggable request-classifier hook to the KV Router that can defer a request, override scheduling inputs, or suggest a worker without overriding explicit pins ([#14123](https://github.com/ai-dynamo/dynamo/pull/14123)), with a deadline-ordered policy queue for every request ([#14176](https://github.com/ai-dynamo/dynamo/pull/14176)), async classifier lifecycle events ([#14177](https://github.com/ai-dynamo/dynamo/pull/14177)), and one plugin registration catalog ([#14149](https://github.com/ai-dynamo/dynamo/pull/14149)). Skipped capacity checks for policy classes with queueing disabled ([#15423](https://github.com/ai-dynamo/dynamo/pull/15423)).
- **ThunderAgent Builtin Router Plugin:** Shipped ThunderAgent as a builtin router plugin enabled through `--router-policy-config` ([#15164](https://github.com/ai-dynamo/dynamo/pull/15164)), made its cost model DP-rank aware so SGLang data-parallel attention workers no longer fail program-lifecycle requests ([#14000](https://github.com/ai-dynamo/dynamo/pull/14000)), and made it honor the Router's pinned worker and check that worker's live capacity ([#15290](https://github.com/ai-dynamo/dynamo/pull/15290)).
- **KV Router Slot Tracker Recovery:** Cut slot tracker overhead by sharding its locks ([#15531](https://github.com/ai-dynamo/dynamo/pull/15531)), tied standalone replica sync to each request's reservation so peer routers no longer see a re-added request's prefill as complete ([#15578](https://github.com/ai-dynamo/dynamo/pull/15578)), reworked the recovery snapshot cache ([#15551](https://github.com/ai-dynamo/dynamo/pull/15551)), and restored buffer-first gap recovery that keeps the existing index on a KV event gap ([#14627](https://github.com/ai-dynamo/dynamo/pull/14627)).
- **Planner GPU Budget Enforcement:** Added runtime reconfiguration of endpoint floors and `min_gpu_budget`/`max_gpu_budget` bounds through `PATCH /v1/min-endpoints` ([#14218](https://github.com/ai-dynamo/dynamo/pull/14218)), treated `min_gpu_budget` as a scale-down guard ([#14231](https://github.com/ai-dynamo/dynamo/pull/14231)), and preserved the decode replica count when a raised GPU floor would reduce it ([#15466](https://github.com/ai-dynamo/dynamo/pull/15466)). Applied `min_endpoint` in single-pool load scaling ([#15530](https://github.com/ai-dynamo/dynamo/pull/15530)) and distinguished startup from drain and rollout so falling demand cannot cancel pending capacity or drain serving workers ([#14671](https://github.com/ai-dynamo/dynamo/pull/14671)).
- **Planner Gym Autoscaler Evaluation:** Added an experimental Planner Gym under `gyms/planner-gym` that compares Planner, KEDA/HPA-style, reactive, and static autoscaling policies ([#15576](https://github.com/ai-dynamo/dynamo/pull/15576)), resolved its defaults through the production Planner configuration ([#15678](https://github.com/ai-dynamo/dynamo/pull/15678)), and removed stale offline replay restrictions so Planner policies run on agentic Mooncake and Dynamo or Weka traces ([#15435](https://github.com/ai-dynamo/dynamo/pull/15435)).
- **Phase-Aware Prefill Accounting:** Gated prefill-start recording off for decode-only requests ([#14019](https://github.com/ai-dynamo/dynamo/pull/14019)), moved SGLang prefill completion to after the background prefill stream ends ([#14968](https://github.com/ai-dynamo/dynamo/pull/14968)), and fixed output-block undercounting across block boundaries and batched those updates ([#14613](https://github.com/ai-dynamo/dynamo/pull/14613), [#15448](https://github.com/ai-dynamo/dynamo/pull/15448)).
- **Direct ZMQ Subscriber Multiplexing:** Added opt-in fan-in via `DYN_ROUTER_ZMQ_ENDPOINTS_PER_SUB` so direct-ZMQ subscribers share one SUB socket across many publisher endpoints ([#14219](https://github.com/ai-dynamo/dynamo/pull/14219)), and coalesced pending KV load metrics ([#15587](https://github.com/ai-dynamo/dynamo/pull/15587)).
- **Standalone Indexer Lifecycle Delegates:** Added ownership callbacks to the standalone KV indexer that notify consumers when a block hash gains its first owner or its last owner releases it ([#14945](https://github.com/ai-dynamo/dynamo/pull/14945)), made cleanup safe for absent blocks and backpressure ([#14652](https://github.com/ai-dynamo/dynamo/pull/14652)), and bounded the KV state-agent discovery wait at vLLM startup ([#14003](https://github.com/ai-dynamo/dynamo/pull/14003)).
- **Unified Selection Core:** Unified Dynamo Frontend, standalone selection service, and EPP worker selection on one shared core ([#14570](https://github.com/ai-dynamo/dynamo/pull/14570)) and reduced scheduler and dispatch overhead for large worker pools ([#14666](https://github.com/ai-dynamo/dynamo/pull/14666)).
- **TokenSpeed Disaggregation with KV Routing:** Added prefill/decode disaggregation for the TokenSpeed backend over Mooncake and published native KV-cache events, so the Router can send prompts to the prefill worker already holding their prefix. Included bootstrap validation and transfer-error handling ([#9237](https://github.com/ai-dynamo/dynamo/pull/9237)).
- **Native KV Cache Events:** Added a native TensorRT-LLM KV cache event mode that subscribes directly to each attention-DP rank's ZMQ stream, bypassing the legacy polling and republishing path ([#12167](https://github.com/ai-dynamo/dynamo/pull/12167)).
- **Throughput Scaling Replica Cap:** Added the `max_throughput_scaling_replicas` Planner configuration option, defaulting to 8, and applied it per component to both throughput scale-up and scale-down targets, with capped targets fitted against GPU and power ceilings while preserving explicit endpoint and out-of-band budget recovery ([#14296](https://github.com/ai-dynamo/dynamo/pull/14296)).
- **Relay WAN gRPC Transport:** Added a `dynamo.kvrelay.v1` Protobuf contract and WAN adapter so consumers outside a data center can subscribe to cache locality, readiness, and KV occupancy streams through an opt-in listener ([#14379](https://github.com/ai-dynamo/dynamo/pull/14379)).
- **Router KV Hints Envelope:** Passed Router-produced KV hints to vLLM through vLLM's dedicated KV-hints request argument, keeping hint data separate from the KV connector's `kv_transfer_params` on token, text, and prefill paths. In prefill/decode deployments the hint is applied once on the prefill worker, and decode handoff requests no longer replay it ([#14890](https://github.com/ai-dynamo/dynamo/pull/14890)).
- **Centralized Router Policy Configuration:** Moved Router scoring knobs into `--router-policy-config` with a `router` section for shared cache settings, deprecated the six scoring flags and `--load-aware` while their behavior remains available for migration, and removed `router_credit_blocks` from the overlap-query response ([#15202](https://github.com/ai-dynamo/dynamo/pull/15202)). Added a `soft-pin-repin` policy example for soft session-affinity rebinding ([#14152](https://github.com/ai-dynamo/dynamo/pull/14152)).
- **Worker KV Reuse Telemetry:** Added router metrics for KV cache reuse per routing attempt across SGLang, TensorRT-LLM, and vLLM, labeled by `phase` and `model`, so operators can compare routed prompt tokens against engine cache hits ([#15443](https://github.com/ai-dynamo/dynamo/pull/15443)).

### KV Block Manager

- **File-Based Relay Source Mode:** Added a `--sources-file` option to KV DC Relay that selects Dynamo namespaces from a versioned JSON file with live reload, and an `/engine/state` route reporting readiness ([#14807](https://github.com/ai-dynamo/dynamo/pull/14807)).

### Multimodal & Diffusion

- **Nemotron Omni Multimodal Routing:** Added exact multimodal KV routing for Nemotron 3 Nano Omni images by modeling vLLM dynamic-resolution geometry and model-specific delimiters ([#14564](https://github.com/ai-dynamo/dynamo/pull/14564)), and for video by sampling and decoding frames and grouping them into temporal tubelets ([#14653](https://github.com/ai-dynamo/dynamo/pull/14653)).
- **Cascaded Nemotron Speech Example:** Added a self-contained deployment example exposing Nemotron ASR, LLM, and TTS endpoints through `/v1/realtime` transcription and streaming `/v1/audio/speech`, with a three-GPU DynamoGraphDeployment and a smoke client ([#12567](https://github.com/ai-dynamo/dynamo/pull/12567)), and added a client-driven ASR-to-LLM handoff for speculative prefix-cache warming ([#14327](https://github.com/ai-dynamo/dynamo/pull/14327)).

## Looking Ahead

### Runtime Router Policy Management

A `/router_policy` API on the Frontend reads and updates live worker-selection parameters and busy thresholds without a restart.

### Planner Reconfiguration & Batch Scheduling

Runtime reconfiguration extends beyond GPU budgets to a running Planner's SLA targets and load predictor. An opt-in batch scheduling policy reserves capacity for online traffic, with the Batch API served through the Frontend.

### Generation Artifacts for RL

vLLM workers can deliver bounded generation artifacts inline or to object stores for reinforcement learning pipelines.

### Kubernetes Deployment Search

An experimental `v1beta2` API runs simulation-backed deployment searches, and DisaggregatedSet joins Grove as an opt-in workload provider.

## Dynamo Special Interest Groups (SIGs)

Dynamo now has six Special Interest Groups (SIGs). Each SIG runs a public meeting, reviews the Dynamo Enhancement Proposals (DEPs) and PRs in its area, and sets that area's roadmap. Anyone in the community can join, bring a PR or DEP, and be involved in the technical direction of Dynamo.

- **#sig-router:** KV-aware routing, Global Router, and Gateway API routing.
- **#sig-engines:** SGLang, TensorRT-LLM, vLLM, TokenSpeed, and Dynamo Sidecar.
- **#sig-frontend:** Frontend APIs, tool calling, and parsers.
- **#sig-deploy:** Kubernetes Operator, Helm charts, DRA, and Grove.
- **#sig-agents:** Agentic inference, agent hints, and request tracing.
- **#sig-rl:** RL integration, rollouts, and weight updates.
