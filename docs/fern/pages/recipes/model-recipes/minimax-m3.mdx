## Prerequisites

Both targets require:

- A Kubernetes cluster with the Dynamo platform installed. See the [Kubernetes Deployment Guide](../../kubernetes/getting-started/quickstart.mdx).
- GB200 GPU nodes: 8 GPUs for aggregated serving or 24 GPUs for disaggregated serving.
- A rack-scoped NVIDIA ComputeDomain channel `ResourceClaimTemplate`. Update the manifest's `resourceClaimTemplateName` fields to its name.
- A ReadWriteMany storage class that can satisfy the recipe's 1,000 GiB `shared-model-cache` claim.
- A Hugging Face token that can download `nvidia/MiniMax-M3-NVFP4` and `Inferact/MiniMax-M3-EAGLE3-GQA`.
- A vLLM runtime image with the MiniMax M3 support and dependencies required by the selected manifest.

<Warning>
The checked-in manifests are cluster-qualified templates, not directly portable deployments. They contain cluster-specific scheduling, registry, networking, namespace, and ComputeDomain values. The referenced runtime image is not publicly accessible. Replace these values before applying either manifest.
</Warning>

<div data-variant="agg">

The aggregated target also requires the `patch` utility in the runtime image. An init container applies two embedded vLLM scheduler patches and verifies the resulting file hash before workers start. A runtime image with a different vLLM source revision fails this check.

</div>

<div data-variant="disagg">

The disaggregated target requires network-interface annotations and UCX/NCCL interface settings that match the target cluster. It also requires all six workers to use a compatible rack-scoped ComputeDomain channel.

</div>

## Deploy

Set the namespace and create the Hugging Face token secret:

```bash
export NAMESPACE=your-namespace
kubectl create namespace "${NAMESPACE}"
kubectl create secret generic hf-token-secret \
  --from-literal=HF_TOKEN="your-token" \
  -n "${NAMESPACE}"
```

Before applying a deployment manifest, replace these cluster-specific fields:

- Every container and init-container `image` with an image your cluster can pull.
- `imagePullSecrets` with your registry secret, or remove the field when it is not required.
- `priorityClassName`, node selectors, and tolerations with values supported by your cluster.
- Every `resourceClaimTemplateName` with the target cluster's ComputeDomain channel claim template.
- The disaggregated manifest's `metadata.namespace` and `metadata.name`. Set the name to `minimax-m3-disagg-gb200-agentic` for the smoke-test command below.
- The disaggregated manifest's network annotations, topology constraint, `NCCL_SOCKET_IFNAME`, `GLOO_SOCKET_IFNAME`, `UCX_TLS`, and `UCX_NET_DEVICES` values.

Edit `storageClassName` in the model-cache manifest, then populate the cache:

```bash
kubectl apply -f recipes/minimax-m3/model-cache/model-cache.yaml -n "${NAMESPACE}"
kubectl apply -f recipes/minimax-m3/model-cache/model-download.yaml -n "${NAMESPACE}"
kubectl wait --for=condition=complete job/minimax-m3-model-download \
  -n "${NAMESPACE}" --timeout=14400s
```

Apply the selected deployment.

<div data-variant="agg">

```bash
kubectl apply \
  -f recipes/minimax-m3/vllm/agg-gb200-agentic/deploy.yaml \
  -n "${NAMESPACE}"
```

</div>

<div data-variant="disagg">


Monitor the deployment until the frontend and every worker report ready:

```bash

```

## Compare All Targets

Both targets use vLLM, TP4 workers, FP8 KV cache, prefix caching, KV events, KV-aware routing, and EAGLE3 speculative decoding with three speculative tokens.

| | Aggregated | Disaggregated |
| --- | --- | --- |
| **GPUs** | 8x GB200 | 24x GB200 |
| **Workers** | 2 aggregated | 3 prefill + 3 decode |
| **Parallelism** | TP4 per worker | TP4 per worker |
| **GPU memory utilization** | 0.90 | 0.80 prefill / 0.90 decode |
| **Maximum sequences** | 256 | 32 prefill / 256 decode |
| **Maximum batched tokens** | 16,384 | 24,576 prefill / 8,192 decode |
| **KV path** | OffloadingConnector with a 400,000,000,000-byte CPU budget setting | NIXL transfer between prefill and decode |
| **Maximum context** | 1,048,576 | 1,048,576 |

## Notes

- Both manifests set `--language-model-only`; these targets serve text requests only.
- Both manifests pin the model checkpoint and the EAGLE3 checkpoint to specific Hugging Face revisions.
- The aggregated target uses vLLM's `OffloadingConnector` with `CPUOffloadingSpec` and sets `cpu_bytes_to_use` to `400000000000`.
- The disaggregated target uses `NixlConnector` with `kv_role=kv_both` on prefill and decode workers.
- The manifests set `runtimeVersionOverride` to `1.5.0`. This value does not identify a publicly available container image.
