These recipes are the certified subset of the [Nemotron 3.5 Super VL](nemotron-3-5-super-vl-120b-a12b.mdx) recipes. Commercial support covers the enterprise images, not the recipe or configurations derived from it; see [Scope Boundaries](../../enterprise/scope-boundaries.mdx).

## Prerequisites

- A Kubernetes cluster with the Dynamo platform 1.7.0 installed from the enterprise Helm chart. See [Install](../../enterprise/install.mdx).
- A Hugging Face token with access to the checkpoint `nvidia/NVIDIA-Nemotron-3.5-Super-VL-120B-A12B-NVFP4`.
- Room for 16 CPUs and 16 GiB of memory for the frontend pod, and 16 CPUs and 328 GiB of memory per worker pod.

<div data-variant="agg">

- 4 B200 GPUs, and 64 GiB of ephemeral storage per worker pod.

</div>

<div data-variant="disagg">

- 5 B200 GPUs, and 128 GiB of ephemeral storage per worker pod.
- An RDMA device plugin that exposes `rdma/shared_hca`.

</div>

Create the namespace and token secret:

```bash
export NAMESPACE=your-namespace
kubectl create namespace ${NAMESPACE}
kubectl create secret generic hf-token-secret \
  --from-literal=HF_TOKEN="your-token" \
  -n ${NAMESPACE}
```

## Deploy

Each worker downloads the checkpoint into its own `emptyDir` volume at startup, so no model-cache PVC is needed. The startup probe waits up to 4 hours for the download.

<div data-variant="agg">

```bash
export DGD=super-3-5-vllm-b200-agg-swebenchpro
kubectl apply -f recipes/certified/nemotron-3.5-super-vl-120b-a12b/vllm/agg-b200-swebenchpro/deploy.yaml -n ${NAMESPACE}
```

</div>

## Smoke Test

Forward the frontend port:

```bash
kubectl port-forward svc/${DGD}-frontend 8000:8000 -n ${NAMESPACE}
```

Send a request:

```bash
curl http://localhost:8000/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"nvidia/nemotron-3.5-super-vl-120b-a12b","messages":[{"role":"user","content":"Write a one-sentence readiness check."}],"max_tokens":64}'
```

The model reasons before it answers. The deployment parses reasoning with `nemotron_v3` and tool calls with `qwen3_coder`.

## Benchmark

Use the SWE-bench Pro trace-replay workflow in [perf/README.md](https://github.com/ai-dynamo/dynamo/blob/main/recipes/nemotron-3.5-super-vl-120b-a12b/perf/README.md), with `ENDPOINT` set to `http://${DGD}-frontend:8000`. The benchmark Job reads the trace and tokenizer from the `shared-model-cache` PVC, which these recipes do not create; create it from the open-source recipe's [model-cache](https://github.com/ai-dynamo/dynamo/tree/main/recipes/nemotron-3.5-super-vl-120b-a12b/model-cache) manifests first.

## Notes

- The 1.7.0 enterprise images publish on NGC with the Dynamo 1.7.0 release.
- To serve image or video requests, add `--mm-ipc-gpu-memory-gb 10` to every worker and raise the request size limits; see the [recipe README](https://github.com/ai-dynamo/dynamo/blob/main/recipes/certified/nemotron-3.5-super-vl-120b-a12b/README.md#multimodal-workloads). NIM Factory image and video accuracy testing used these settings.
- To serve video on the disaggregated target, also raise `DYN_TCP_REQUEST_TIMEOUT` to 120 s and the NIXL KV lease (`kv_lease_duration`) to 2400 s; the same README section shows how. With the defaults, large videos time out on the way to prefill, and decode can read KV after prefill has released it.
- The disaggregated decode workers use `NixlConnector` alone, matching the open-source recipe.
