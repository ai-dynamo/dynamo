## Prerequisites

- A Dynamo Platform install on your Kubernetes cluster. See the [Kubernetes quickstart](/dynamo/kubernetes/getting-started/quickstart).
- A ReadWriteMany storage class. The checkpoint is 510 GB over 48 shards; the PVC in this recipe requests 600 Gi.
- Outbound access to Hugging Face for the download Job. The repository is public; the Job reads `HF_TOKEN` from the `hf-token-secret` Secret.

## Deploy

Create the namespace and Hugging Face secret:

```bash
export NAMESPACE=your-namespace
kubectl create namespace ${NAMESPACE}
kubectl create secret generic hf-token-secret \
  --from-literal=HF_TOKEN="your-token" \
  -n ${NAMESPACE}
```

Create the model cache and download the checkpoint. Edit `storageClassName` in `model-cache.yaml` to a ReadWriteMany class on your cluster. The Job pins snapshot `1bae0e1088993b9b82de08f59de5be5a34e42170`, which the workers also load by revision.

```bash
kubectl apply -f recipes/deepseek-v4.1-flash-1017/model-cache/model-cache.yaml -n ${NAMESPACE}
kubectl apply -f recipes/deepseek-v4.1-flash-1017/model-cache/model-download.yaml -n ${NAMESPACE}
kubectl wait --for=condition=Complete job/model-download -n ${NAMESPACE} --timeout=7200s
```

Then send a request in a separate terminal:

```bash
curl -s localhost:8000/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "deepseek-ai/DeepSeek-V4.1-Flash-1017",
    "messages": [{"role": "user", "content": "What is 17 * 23?"}],
    "max_tokens": 4096
  }' | jq -r '.choices[0].message | .content // .reasoning_content'
```

This is a reasoning model. The chain of thought is returned in `reasoning_content` and the answer in `content`; a small `max_tokens` can leave `content` empty because reasoning consumes the budget.

## Expected Performance

AgentX trace replay, 3600 s window. A point passes when decode p50 is at least 50 tok/s/user, TTFT p50 is under 2 s, and errors are under 5%. tok/s/GPU is total output tokens per second divided by the GPU count.

<Warning>
These throughput figures force DSpark's acceptance length to the value measured on SPEED-Bench (3.19 on H200, 3.4 on B200 and GB300), because the trace carries filler text that makes real acceptance unrepresentative. That mode fabricates accepted tokens, so treat the numbers as an upper bound. The shipped manifests use real acceptance; [`perf/README.md`](https://github.com/ai-dynamo/dynamo/blob/main/recipes/deepseek-v4.1-flash-1017/perf/README.md) gives the setting for reproducing these runs.
</Warning>

## Compare All Targets

| Target | GPUs | Topology | Concurrency | tok/s/GPU (synthetic acceptance) |
| --- | --- | --- | --- | --- |
| `agg-h200-agentx` | 4x H200 | Aggregated, TP4 | 108 | 482.1 |
| `disagg-h200-agentx` | 20x H200 | 3P2D | 480 | 384.8 |
| `agg-b200-agentx` | 4x B200 | Aggregated, TP4 | 400 | 1,552.4 |
| `disagg-b200-agentx` | 16x B200 | 3P1D | 1408 | 1,478.4 |
| `agg-gb300-agentx` | 4x GB300 | Aggregated, 2x TP2 | 616 | 2,320.1 |
| `disagg-gb300-agentx` | 8x GB300 | 2P1D | 920 | 2,162.3 |

Aggregated is the recommended default on all three GPUs. On H200 it is 1.25x better per GPU than disaggregated. On B200 and GB300 it leads by 5% and 7%, so choose disaggregated only when a single deployment must carry the higher concurrency or when decode speed per user matters (100 versus 59 tok/s/user on B200, 154 versus 60 on GB300).

## Notes

- **Spec-decode settings must match across prefill and decode.** A mismatch changes KV block geometry and produces wrong output rather than an error.
- **Send a session ID.** The router keeps each session on the worker that holds its prefix cache, which is where most of the throughput comes from on multi-turn traffic. The benchmark Job sets `AIPERF_HTTP_X_DYNAMO_SESSION_ID_FROM_CORRELATION_ID=1` for this; your own clients need to send a session ID for the same effect.
- **KV events.** The aggregated and B200/GB300 disaggregated targets publish KV events so the router sees exact cache contents. H200 disaggregated uses approximate routing (`--no-kv-events`).
- **GB300 aggregated runs two TP2 workers** that together fill one 4-GPU node.
- **Evaluating the model.** Give it a large token budget (65,536) because it reasons before answering. Set `reasoning_effort` to `high` if you set it; `medium` and integer values are rejected with HTTP 400. The frontend rejects an empty `stop` array, which some evaluators send, so drop that field.
- **Multimodal input is enabled** (`--enable-multimodal`) on every target.
