**Experimental.** Serve [Motif-Technologies/Motif-3-NVFP4](https://huggingface.co/Motif-Technologies/Motif-3-NVFP4) with NVIDIA Dynamo and vLLM. Both targets use tensor parallelism of two (TP2), expert parallelism, multi-token prediction with two speculative tokens (MTP2), and a 262,144-token context. The disaggregated target separates three prefill workers from one decode worker (3P1D), transfers KV cache through NIXL, and routes requests using worker cache events and active load.

## Prerequisites

- A Kubernetes cluster with the [Dynamo platform installed](../../kubernetes/getting-started/quickstart.mdx) and a shared ReadWriteMany model-cache volume.
- A Hugging Face token with access to the checkpoint, used by the model-download Job.

<div data-variant="agg">

- Two available B200 GPUs on one node.

</div>

<div data-variant="disagg">

- Eight available B200 GPUs. Each TP2 worker occupies two GPUs on one node; configure the fabric for NIXL/UCX transfer between nodes.
- Image-pull credentials with read access to `nvcr.io/nvstaging/nim/motif-3`, configured through the namespace's ServiceAccount or a site Kustomization. This target pins a private image by digest.

</div>

Run the following commands from the repository root. Create a namespace and download secret if they do not already exist:

```bash
export NAMESPACE=your-namespace
kubectl create namespace "${NAMESPACE}"
kubectl create secret generic hf-token-secret \
  --from-literal=HF_TOKEN="$HF_TOKEN" \
  -n "${NAMESPACE}"
```

## Deploy

Reuse a populated `shared-model-cache` PVC when available. Otherwise, set `storageClassName` in the [model-cache manifest](https://github.com/ai-dynamo/dynamo/blob/main/recipes/motif-3/model-cache/model-cache.yaml), then create the cache and download the checkpoint. For Nscale, use `storageClassName: vast`.

```bash
kubectl apply -f recipes/motif-3/model-cache/model-cache.yaml -n "${NAMESPACE}"
kubectl apply -f recipes/motif-3/model-cache/model-download.yaml -n "${NAMESPACE}"
kubectl wait --for=condition=Complete job/model-download -n "${NAMESPACE}" --timeout=7200s
```

<div data-variant="agg">

Apply the [aggregated manifest](https://github.com/ai-dynamo/dynamo/blob/main/recipes/motif-3/vllm/agg-b200-chat/base/deploy.yaml):

```bash
kubectl apply -f recipes/motif-3/vllm/agg-b200-chat/base/deploy.yaml -n "${NAMESPACE}"
kubectl get dgd motif3-agg-b200 -n "${NAMESPACE}" -w
```

For Nscale B200 selection and GPU tolerations, apply the [aggregated Kustomization](https://github.com/ai-dynamo/dynamo/tree/main/recipes/motif-3/vllm/agg-b200-chat/kustomize) instead:

```bash
kubectl apply -k recipes/motif-3/vllm/agg-b200-chat/kustomize -n "${NAMESPACE}"
```

The aggregated Kustomization fetches the shared Dynamo OpenAPI schema from a pinned GitHub commit, so rendering requires Git and network access. This target uses two GPUs on one node and does not request RDMA devices.

</div>

<div data-variant="disagg">

Configure GPU node selection and fabric resources for your cluster, then apply the [generic 3P1D manifest](https://github.com/ai-dynamo/dynamo/blob/main/recipes/motif-3/vllm/disagg-b200-chat/deploy-generic-3p1d-kv.yaml):

```bash
kubectl apply -f recipes/motif-3/vllm/disagg-b200-chat/deploy-generic-3p1d-kv.yaml -n "${NAMESPACE}"
kubectl get dgd motif3-disagg-b200 -n "${NAMESPACE}" -w
```

For Nscale, apply the [Nscale 3P1D manifest](https://github.com/ai-dynamo/dynamo/blob/main/recipes/motif-3/vllm/disagg-b200-chat/deploy-nscale-3p1d-kv.yaml) instead. It selects `g.192.b200.8` B200 nodes, requests one `rdma/shared_ib` device per worker, and sets `UCX_TLS=rc_x,rc,cuda_copy,cuda_ipc`:

```bash
kubectl apply -f recipes/motif-3/vllm/disagg-b200-chat/deploy-nscale-3p1d-kv.yaml -n "${NAMESPACE}"
```

Both variants update the same `motif3-disagg-b200` deployment. Wait for the frontend and all four workers to become ready. The frontend uses no GPU; serving uses eight GPUs in total.

</div>

## Benchmark

Stage the complete [`8k_1k_70kv_chat_new_noschedule_short_15perc.jsonl` trace](https://github.com/ai-dynamo/dynamo/blob/main/recipes/kimi-k2.6/perf/traces/8k_1k_70kv_chat_new_noschedule_short_15perc.jsonl) at `/shared-model-cache/traces/8k_1k_70kv_chat_new_noschedule_short_15perc.jsonl`.

<div data-variant="agg">

The [aggregated AIPerf Job](https://github.com/ai-dynamo/dynamo/blob/main/recipes/motif-3/perf/perf.yaml) uses concurrency 11:

```bash
kubectl apply -f recipes/motif-3/perf/perf.yaml -n "${NAMESPACE}"
kubectl logs -f job/motif3-aiperf-job -n "${NAMESPACE}"
```

</div>

<div data-variant="disagg">

Use AIPerf 0.13.0 with Transformers 5.19.0, Tokenizers 0.23.2, and huggingface-hub 1.33.0. Run the client in an environment with the model cache mounted at `/shared-model-cache` and network access to the frontend. Prepare a separate tokenizer-only cache using the [client helper](https://github.com/ai-dynamo/dynamo/blob/main/recipes/motif-3/perf/prepare_disagg_client.py):

```bash
export HF_HOME=/tmp/motif3-disagg-client-hf
export HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1
python3 recipes/motif-3/perf/prepare_disagg_client.py
```

The helper verifies the three tokenizer files at model revision `79f2fad1f8229f5db8a7ad08bbd24a20d6fb0bff`. Keep these environment variables when profiling; do not point the client at the workers' full model cache.

Set `variables.concurrency` in the [disaggregated AIPerf configuration](https://github.com/ai-dynamo/dynamo/blob/main/recipes/motif-3/perf/disagg.yaml) for each case. The 3P1D synthetic sweep covers concurrency 8, 16, 32, 40, 48, and 64 with eight client workers. Preserve all 1,805 trace rows; the file is already the 15% sample.

Run a separate warmup. After its requests and NIXL transfers drain, clear all three prefill caches, the decode cache, and the frontend router index. Repeat that reset before each independent case. Use a distinct artifact directory for every run:

```bash
export INFERENCE_URL=http://motif3-disagg-b200-frontend:8000/v1/chat/completions
export AIPERF_ARTIFACT_DIR=/tmp/motif3-3p1d-c8
aiperf config validate recipes/motif-3/perf/disagg.yaml
aiperf profile --config recipes/motif-3/perf/disagg.yaml
```

Report p50 Time To First Token (TTFT), output tokens/sec/GPU, per-user output rate, completed requests, and errors. Divide system throughput by all eight GPUs. Per-user output rate excludes TTFT; specify whether it is a mean or a percentile. Report context-limit rejections separately from unexpected errors.

</div>

Both targets default to **real MTP verification**. For benchmark-only synthetic MTP2 with acceptance length 2.13, change the `SPECULATIVE_CONFIG` ConfigMap reference from `speculative-config` to `speculative-config-synthetic` in the selected deployment source and redeploy. For disaggregation, change **both worker roles**. Synthetic acceptance does not measure real MTP acceptance or output quality. The 2.13 setting comes from the [SPEED-Bench coding domain](https://huggingface.co/blog/nvidia/speed-bench).

## Notes

Both targets use BF16 activations, ModelOpt NVFP4 weights, FP8 KV cache, 128-token blocks, DP1, 0.85 GPU memory utilization, prefix caching, and asynchronous scheduling. The frontend uses the Motif chat processor and tool and reasoning parsers. Frontend and workers use Hugging Face offline mode; populate the shared cache before deployment.

<div data-variant="agg">

The aggregated target uses `nvcr.io/nvidia/ai-dynamo/vllm-runtime:1.5.0-motif-3-dev.1`. Its vLLM package includes Motif compatibility code; do not replace it with an unrelated nightly wheel.

</div>

<div data-variant="disagg">

The digest-pinned disaggregated image includes the Motif NIXL fixes: it validates cache dimensions for each attention backend and retains the NHD layout expected by Motif's attention kernels. Workers start directly with `python3 -m dynamo.vllm`; no startup patch is required. Keep this image for homogeneous TP2 disaggregation.

`NCCL_NET_PLUGIN=none` avoids mixing the image's HPC-X UCX with NIXL's bundled UCX. TP2 collectives stay within each worker's node; NIXL handles cross-node KV transfer. KV-aware routing uses `DYN_ROUTER_MODE=kv`, worker KV events over ZeroMQ, prefix caching, and `PYTHONHASHSEED=0` on every process.

Prefill sets `DYN_HEALTH_CHECK_ENABLED=false` because standalone prefill canaries retain KV blocks without a decode consumer until the transfer lease expires. Engine monitoring and Kubernetes probes remain active. Verify requests through the frontend.

Edit [the recipe base and site components](https://github.com/ai-dynamo/dynamo/tree/main/recipes/motif-3/vllm/disagg-b200-chat/kustomize), then regenerate and check both manifests:
