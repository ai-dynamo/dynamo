## Prerequisites

- Install the [Dynamo Kubernetes Platform](../../kubernetes/getting-started/quickstart.mdx)
  with the `nvidia.com/v1beta1` CRD and the GPUs shown above.
- The manifests use Dynamo 1.6.0 and NVIDIA's Beam runtime images:
  `nvcr.io/nvidia/ai-dynamo/sglang-runtime:1.6.0-beam-1.0-501b-dev.1` or
  `nvcr.io/nvidia/ai-dynamo/vllm-runtime:1.6.0-beam-1.0-501b-dev.1`.
- Prepare the `shared-model-cache` PVC and Hugging Face checkpoints using the
  [model-staging instructions](https://github.com/ai-dynamo/dynamo/blob/main/recipes/beam-1.0-501b/README.md#2-stage-the-model-and-drafter).
  Configure storage, registry access, and GPU placement for your cluster.

Stage the [FP8 checkpoint](https://huggingface.co/reflection/Beam-1.0-501B-A23B-FP8)
for H200 or the [NVFP4 checkpoint](https://huggingface.co/reflection/Beam-1.0-501B-A23B-NVFP4)
for B200, B300, GB200, and GB300, plus the
[DFlash2 drafter](https://huggingface.co/reflection/Beam-1.0-501B-A23B-DFlash2) for every target.

<div data-variant="disagg">

Provide RDMA device access and a working NIXL/UCX path between the prefill and
decode workers. Set the device-plugin resources and `UCX_NET_DEVICES` for your
cluster, and allow the runtime's transport ports between workers. SGLang uses
bootstrap port `8998`; vLLM uses NIXL side-channel port `5600` at each worker's
pod IP. Both roles must use the same checkpoint, KV-cache format, and DFlash2 settings.

</div>

Before deploying, follow the
[model-staging instructions](https://github.com/ai-dynamo/dynamo/blob/main/recipes/beam-1.0-501b/README.md#2-stage-the-model-and-drafter)
for your selected `PROFILE`. Use the namespace containing that staged model cache.
Use your cluster overlay for GPU and CPU-architecture placement when nodes differ.
On a cluster with matching hardware, apply the portable manifest below:

```bash
export NAMESPACE=beam
PROFILE_TARGET=${PROFILE#*/}
PROFILE_TARGET=${PROFILE_TARGET%-nvfp4}
export DEPLOYMENT="beam-${PROFILE%%/*}-${PROFILE_TARGET#*-}-${PROFILE_TARGET%%-*}"
kubectl apply -n "$NAMESPACE" -f "recipes/beam-1.0-501b/$PROFILE/deploy.yaml"
kubectl wait -n "$NAMESPACE" --for=condition=Ready "dgd/$DEPLOYMENT" --timeout=7200s
kubectl port-forward -n "$NAMESPACE" "svc/$DEPLOYMENT-frontend" 8000:8000
```

## Configurations

SGLang and vLLM share these defaults and deployment layouts. Blackwell includes
B200, B300, GB200, and GB300; P/D means prefill/decode.

| Shared setting | Default |
| --- | --- |
| Context | Up to 1,048,576 tokens |
| KV cache dtype | `fp8_e4m3` |
| KV page / block size | 64 tokens |
| DFlash2 | Enabled, block length 8 |
| Routing | KV-aware |

| Setting | H200 aggregated | H200 disaggregated | Blackwell aggregated | Blackwell disaggregated |
| --- | --- | --- | --- | --- |
| Weight precision | FP8 | FP8 | NVFP4 | NVFP4 |
| TP per worker | 8 | 8 | 4 | 4 |
| Worker replicas | 1 | 1 P + 1 D | 2 | 1 P + 1 D |
| Total GPUs | 8 | 16 | 8 | 8 |
| KV transfer | — | NIXL | — | NIXL |

The selected `deploy.yaml` contains the attention and MoE backends, batching,
cache, and memory settings. Measured performance results are not included.
