Clone the NVIDIA Dynamo repository before running these examples. Each entry states the directory
from which to run its command. Review the source and install the backend-specific dependencies before
starting a deployment.

## Triton Server

<Warning>
**Experimental / Proof of Concept.** The Triton Server integration is not a production deployment
recipe. It builds and serves the sample identity model through Dynamo's KServe gRPC endpoint.
</Warning>

<AccordionGroup>
<Accordion title="Identity model with Triton Server">

Starts the Dynamo frontend and one Triton worker on the same host. The default model repository
contains the `identity` model. The example requires one NVIDIA GPU and a locally built Triton backend
or the example container image.

**Configuration**

| Option or variable | Default | Description |
| --- | --- | --- |
| `--model-name` | `identity` | Triton model to load. |
| `--model-repository` | `examples/backends/tritonserver/model_repo` | Triton model repository. |
| `--backend-directory` | `examples/backends/tritonserver/backends` | Directory containing the built Triton backends. |
| `DYN_DISCOVERY_BACKEND` | `file` | Dynamo discovery backend. |
| `DYN_HTTP_PORT` | `8000` | HTTP port exposed by the Dynamo frontend. |
| `DYN_SYSTEM_PORT` | `8081` | Worker system and metrics port. |

```bash
cd examples/backends/tritonserver
./launch/identity.sh
```

[View the launch script.](https://github.com/ai-dynamo/dynamo/blob/main/examples/backends/tritonserver/launch/identity.sh)
The bundled model configuration is shown below.

</Accordion>

## Custom Encoders

See [Custom Vision Encoders](../../use-cases/multimodal-serving/custom-vision-encoders.md) for the
encoder interface, request format, and validation workflow.

<AccordionGroup>
<Accordion title="Text Decoder with a Custom Encoder">

Starts the frontend and one vLLM worker with an in-process `CustomEncoder`. The default model is
`Qwen/Qwen2.5-1.5B-Instruct`; the default teaching encoder substitutes a fixed phrase embedding for
the image input. The launcher uses one GPU by default.

**Configuration**

| Option or variable | Default | Description |
| --- | --- | --- |
| `--model` / `DYN_MODEL` | `Qwen/Qwen2.5-1.5B-Instruct` | Text model loaded by vLLM. |
| `--encoder-class` / `DYN_ENCODER_CLASS` | `examples.custom_encoder.hitchhikers_vision_encoder.HitchhikersVisionEncoder` | Python class that supplies the custom embeddings. |
| `--gpu` / `DYN_WORKER_GPU` | `0` | GPU used by the worker. |
| `DYN_MAX_MODEL_LEN` | `4096` | Maximum model context length. |

```bash
./examples/custom_encoder/launch/agg_custom.sh
```

[View the launch script.](https://github.com/ai-dynamo/dynamo/blob/main/examples/custom_encoder/launch/agg_custom.sh)
</Accordion>
<Accordion title="Qwen3.5 with a Teaching Vision Encoder">

Starts one aggregated vLLM worker with the Qwen3.5-native multimodal path. The default model is
`Qwen/Qwen3.5-0.8B`, and the launcher uses one GPU by default.

**Configuration**

| Option or variable | Default | Description |
| --- | --- | --- |
| `--model` / `DYN_MODEL` | `Qwen/Qwen3.5-0.8B` | Qwen3.5 model loaded by vLLM. |
| `--encoder-class` / `DYN_ENCODER_CLASS` | `examples.custom_encoder.qwen3_5_vision_encoder.Qwen35VisionEncoder` | Teaching encoder implementation. |
| `--gpu` / `DYN_WORKER_GPU` | `0` | GPU used by the worker. |
| `DYN_MAX_MODEL_LEN` | `4096` | Maximum model context length. |
| `DYN_MAX_NUM_SEQS` | `2` | Maximum number of concurrent sequences. |

```bash
./examples/custom_encoder/launch/agg_qwen3_5_native.sh
```

[View the launch script.](https://github.com/ai-dynamo/dynamo/blob/main/examples/custom_encoder/launch/agg_qwen3_5_native.sh)
</Accordion>
</AccordionGroup>

## FastVideo Diffusers

<Warning>
**Experimental.** These launchers run the FastVideo custom worker used by the text-to-video example.
See [Text-to-Video](../../use-cases/diffusion/workflows/text-to-video.md) for prerequisites and the
request format.
</Warning>

<AccordionGroup>
<Accordion title="Local FastVideo Worker">

Starts the Dynamo frontend and a FastVideo worker with file-based discovery. The default model is
`FastVideo/FastWan2.1-T2V-1.3B-Diffusers`, and `NUM_GPUS` defaults to `1`.

```bash
./examples/diffusers/local/run_local.sh
```

[View the launch script.](https://github.com/ai-dynamo/dynamo/blob/main/examples/diffusers/local/run_local.sh)
</Accordion>
<Accordion title="Docker Compose FastVideo Deployment">

Builds the example image and starts the frontend plus one to eight workers. The worker defaults to
`FastVideo/FastWan2.1-T2V-1.3B-Diffusers`, and each worker reserves one NVIDIA GPU. Set
`COMPOSE_PROFILES` to the desired worker count before starting the stack.

```bash
cd examples/diffusers/local
COMPOSE_PROFILES=1 docker compose up --build
```

## Development and Testing

The sample backend launchers do not load a production model. Use them for CPU-only development,
protocol checks, and topology smoke tests.

<AccordionGroup>
<Accordion title="Aggregated Echo Backend">

Starts the frontend and one CPU-only sample worker. The registered model name defaults to
`sample-model`.

```bash
cd examples/backends/sample
./launch/agg.sh
```

[View the launch script.](https://github.com/ai-dynamo/dynamo/blob/main/examples/backends/sample/launch/agg.sh)
</Accordion>
<Accordion title="Disaggregated Echo Backend">

Starts CPU-only prefill and decode sample workers plus the frontend. The registered model name
defaults to `sample-model`.

```bash
cd examples/backends/sample
./launch/disagg.sh
```

[View the launch script.](https://github.com/ai-dynamo/dynamo/blob/main/examples/backends/sample/launch/disagg.sh)
</Accordion>
<Accordion title="Aggregated Sample Diffusion Backend">

Exercises the image-generation API through the CPU-only sample diffusion engine. It does not load a
real diffusion model.

```bash
cd examples/backends/sample
./launch/agg_diffusion.sh
```

[View the launch script.](https://github.com/ai-dynamo/dynamo/blob/main/examples/backends/sample/launch/agg_diffusion.sh)
</Accordion>
<Accordion title="Aggregated Multimodal Smoke Test">

Runs the CPU-only sample backend with the repository's tiny test model to check aggregated
multimodal request handling.

```bash
cd examples/backends/sample
./launch/multimodal_agg.sh
```

[View the launch script.](https://github.com/ai-dynamo/dynamo/blob/main/examples/backends/sample/launch/multimodal_agg.sh)
</Accordion>
<Accordion title="Disaggregated Multimodal Smoke Test">

Runs CPU-only encode, prefill, and decode sample workers with the repository's tiny test model.

```bash
cd examples/backends/sample
./launch/multimodal_disagg.sh
```

[View the launch script.](https://github.com/ai-dynamo/dynamo/blob/main/examples/backends/sample/launch/multimodal_disagg.sh)
</Accordion>
</AccordionGroup>
