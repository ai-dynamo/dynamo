See [Text-to-Video](../../use-cases/diffusion/workflows/text-to-video.md) and
[Image-to-Video](../../use-cases/diffusion/workflows/image-to-video.md) for request formats.
Run local commands from the repository root; review each script’s model and build requirements.

<Warning>
**Experimental Kubernetes examples.** T2V and I2V were validated on September 22, 2026 with one
amd64 H100 80 GB worker each, a Dynamo 1.4.2 frontend/operator, and the digest-pinned custom worker
image in the manifests. This is not an official release image. It includes both the video
`response_format` forwarding fix and an FFmpeg RGB-to-YUV color-conversion fix. Do not substitute
stock 1.4.2 or an arbitrary nightly and assume equivalent results. Keep `--enforce-eager` and
`runtimeVersionOverride: 1.4.2` on both components as tested.

Replace the cache PVC/subpath and add your cluster’s GPU node selectors before applying.
`HF_HUB_OFFLINE=1` requires complete model snapshots in the read-only cache; prepare `hf-token-secret`
with `HF_TOKEN`. Run the two deployments sequentially for a one-GPU budget. Request
`response_format: "b64_json"` and decode the returned MP4 on the client: `file://` URLs are pod-local.
These were functional checks, not performance benchmarks; changing infrastructure requires revalidation.
</Warning>
