A `DynamoGraphDeploymentRequest` (DGDR) describes a model, workload, hardware, and optional latency
targets. Dynamo profiles it and generates the `DynamoGraphDeployment` (DGD) that serves traffic, so you
don't write the complete DGD yourself.

**Prerequisites:** [Dynamo Kubernetes platform](../../kubernetes/installation/install-dynamo.md)

- With a namespace-restricted operator, set `hardware.gpuSku`, `hardware.vramMb`, and
  `hardware.numGpusPerNode`.
- With a local operator build that has no release version, set `spec.image` to a compatible
  `dynamo-planner` image. Release installations select it automatically.

## Inspect the Result

Watch the request until it reaches `Deployed` or `Ready`:

```bash
kubectl get dgdr <request-name> -n ${NAMESPACE} -w
```

For a request with `autoApply: false`, extract the generated DGD:

```bash
kubectl get dgdr <request-name> -n ${NAMESPACE} \
  -o jsonpath='{.status.profilingResults.selectedConfig}' > generated-dgd.yaml
```

See [Auto Deploy with DGDR](../../kubernetes/auto-deployment/auto-deploy-with-dgdr.md) for the task-oriented workflow and the
[DGDR Reference](../../reference/kubernetes-api/dynamo-graph-deployment-request.mdx) for field definitions, lifecycle phases, and
validation behavior.
