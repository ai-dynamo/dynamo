# lib/frontend-protocols

`dynamo-frontend-protocols` owns the messages the Dynamo frontend exchanges with clients and with workers: the OpenAI surface (`openai`: chat completions, completions, responses, embeddings, images, audio, video, with their validation, strict schema, tool handling, stream parsing and aggregation), the Anthropic Messages surface (`anthropic`), the tensor protocol (`tensor`), the SSE codec (`codec`), and the frontend-to-worker contract (`common`: `PreprocessedRequest`, `LLMEngineOutput`, `BackendOutput`, routing extensions, request timing, metadata upload). `types` holds the engine type aliases over these messages. It defines, validates, converts and aggregates messages; it serves no requests.

- Depends on (Dynamo crates): `dynamo-runtime`, `dynamo-model-card`, `dynamo-admission`, `dynamo-scheduler`, `dynamo-router-protocol`, `dynamo-kv-hashing`, `dynamo-kv-hints`, `dynamo-lora`, and the published `dynamo-protocols`, `dynamo-parsers`, `dynamo-parsers-v2`, `dynamo-renderer`, `dynamo-tokenizers`.
- Must not depend on: `dynamo-llm` or any crate above it, nor on `dynamo-memory`, NIXL, CUDA or the `image` crate. Decoded media crosses as the plain `common::decoded_media` wire types; the media loader in `dynamo-llm` converts its own descriptor into them and tests that both serialize to the same bytes.
- Every type here is a wire contract with clients or with workers at other versions (N-2, see `lib/llm/AGENTS.md`). Before changing a request or response field, read the [protocol field handling contract](../../docs/fern/pages/developer-guide/knowledge-base/modular-components/frontend/protocol-field-handling.md), and keep serde compatibility tests next to the type.
- Hosts import this crate directly; `dynamo-llm` does not re-export it. Behaviour that needs the preprocessor, the router, or an HTTP or gRPC service belongs in `dynamo-llm` as a free function or an extension trait, not as an impl here.
- Features: `media-ffmpeg` adds the video variant of the decoded-media metadata (`dynamo-llm` forwards its own feature); `testing` exports the `test_fixtures` modules that `dynamo-llm`'s tests reuse.
- Tests read fixtures under `lib/llm/tests/data`. The JSON schemas in `src/openai/media_schemas` are generated by the tests there and feed `scripts/generate_media_protocols.py`.
- Check: `cargo test -p dynamo-frontend-protocols`, and `cargo tree -p dynamo-frontend-protocols | grep -E "dynamo-llm|dynamo-memory|nixl-sys|cudarc"` must print nothing.
