# lib/multimodal

- This crate owns the multimodal identity both ends of the wire compute: the per-block and per-request metadata (`BlockMmObjectInfo`, `BlockExtraInfo`, `RequestMmObjectInfo`, `RequestExtraInfo`, `RequestExtraInfo::to_block_level`), the pad and identifier rules (`hash_mm_identifier`, `pad_value_for_mm_hash`, `MM_PAD_SHIFT_VALUE`, `MM_PAD_HASH_MASK`), and the vLLM extra-key marker (`mark_mm_hash_for_extra_key`, `parse_mm_hash_from_extra_key`). Nothing else belongs here.
- Depend on serde and xxhash-rust only. Never add a `dynamo-*` crate (this is a leaf below `dynamo-kv-hashing`, `dynamo-kv-events`, and `dynamo-scheduler`), tokio, anyhow, tracing, thiserror, axum, reqwest, zmq, or prometheus; the gate checks the direct set exactly and forbids the rest in the closure.
- Stays elsewhere: the vLLM ZMQ extra-key codec (`DYNAMO_CACHE_SALT_PREFIX`, `extra_keys_to_cache_namespace`, `extra_keys_to_block_mm_infos`; they take the wire item `ExtraKeyItem`) and the placeholder-run normalization (`convert.rs`) in `dynamo-kv-events`; `compute_block_hash*`, which consumes `BlockExtraInfo`, in `dynamo-kv-hashing`; `dynamo_kv_hashing::RequestMmObjectInfo`, a different shape with the same name for the PLH request (a follow-up unifies them; do not touch it from here); model-specific multimodal routing (`preprocessor/mm_routing/*`, the embedding caches, the encoder router) in `lib/llm`.
- The pad constants track SGLang's `MultimodalItem._compute_pad_value`; `pad_value_matches_sglang_protocol` pins them. Changing any rule here changes what engines publish and what the router matches; keep the known-answer tests next to the function.
- Every public item is documented (`#![deny(missing_docs)]`); no `#[doc(hidden)]`. The public surface is a committed snapshot (`public-api.txt`); run `scripts/router_public_api_check.sh --update` and review the diff when it changes.
- Run `scripts/router_layering_check.sh` before committing; CI runs it with `--host`. Keep this file and its `CLAUDE.md` twin (exactly `@AGENTS.md`) together.
